# 角色、分镜与互动场景

主角 **芯芯**是背着背包、系橙色围巾的绿色机器人。四位区域伙伴分别为新手村的猫头鹰**咕咕**、逻辑森林的叶子精灵**芽芽**、工具工坊的海狸师傅**铆铆**和芯片城的猫工程师**洛洛**。角色、场景和动作使用原创 SVG，统一配色、线条和造型，无需图片服务或网络字体。

## 每关怎样玩

1. 点击“播放剧情”看完四幕，也可以逐幕切换、暂停或从头看。
2. 对照 NPC 的解释、场景变化和当前高亮代码。点击角色头像可以与伙伴对话。
3. 在“换个输入”中选一个情况，观察边界、小数、空输入等产生的变化。
4. 点击“把这段演示送到实验室”，再运行真实 Tcl。这个按钮会替换当前编辑器代码，页面已注明。
5. 回到关卡原任务，完成代码并“提交挑战”。只有通过原任务全部检查，才会获得通关奖励。

共有 20 个独立场景、80 幕解释、60 组可运行输入。仓库的每份关卡讲义也有同一套角色绘制的静态场景插图。示例包括变量背包、三扇括号门、药水能量、金币门、物品格、循环采集、路牌清理、精灵补给、技能卡、字典档案、文件日记、安全宝箱、平均值机、命名空间分区、报告放大镜、类与对象工厂、教学流程和时序侦探台。

## 图解和真实运行的关系

剧情是围绕**所选示例代码**编写的教学分镜；其“预期结果”经过原生 Tcl 和网页实际使用的 WebAssembly 引擎验证。第 19 关“周期为零”故意演示 `error`，不会给出正常流程结果。

分镜顺序是概念解释顺序，**不是逐行调试器**。例如定义过程、调用过程和返回值的关系，会按适合教学的顺序展开。高亮行来自所选的完整代码，页面明确标注了这一点。

可以随意改写实验室中的 Tcl。“芯芯的实时回声”显示这次 Worker 的实际输出或错误，不会把固定示例输出冒充运行结果，也不会从任意 Tcl 脚本推测场景动作。只有通过整关检查才将故事切到任务默认输入的结尾。

演示选择和播放位置不计入 XP、不改变通关状态。执行演示、失败和修改草稿均不会伪造通关；XP 仍只发放一次。角色介绍和动作不需要登录。

## 继续维护

- 修改剧情源文件 `scripts/build_adventures.py`，运行它生成 `site/adventures.json`。默认输入来自课程解法；替代输入通过显式替换生成。
- 运行 `node scripts/export_artwork.mjs` 导出各关静态插图和角色图鉴，供 GitHub 讲义直接展示。
- 原创角色和场景图形在 `site/adventure-art.js`，交互与运行反馈在 `site/adventure.js`。
- 修改课程解法后，先生成课程，再生成剧情；行号映射会重新计算。
- `tests/adventures.py` 在临时目录执行全部 60 组输入，包括预期错误。
- `tests/wasm.mjs` 在网页的同一份 Tcl 8.6.6 引擎执行全部输入及原有挑战检查。
- `tests/artwork.py` 检查全部 240 个场景帧的 SVG 结构和无效坐标。

动作动画可关闭，默认遵循系统“减少动态效果”设置；播放由学习者主动触发。所有控制使用原生按钮，支持键盘；当前分镜和运行反馈有文字说明。离开关卡或切到后台会停止自动播放。手机使用场景中心近景，角色在对话区保留，不需要横向拖动整页。
